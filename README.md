# ai-kit

English | [简体中文](README.zh-CN.md)

An engineering collaboration toolkit for AI coding agents (Claude Code, Codex): project memory templates, wrap-up and distill skills, tiered implementer agents and an independent verifier agent, guardrail hooks, a status-display mod, and the write-ups behind them.

## What problem it solves

- **Memory is lost when you switch tools or sessions.** Progress, decisions, and gotchas are recorded in the project's `.ai/` files, and Claude Code and Codex read the same copy.
- **An agent saying "done" can't be trusted.** Implementation goes to a subagent; verification goes to a read-only verifier that has no implementation history.
- **The same mistakes keep happening.** Gotchas are first recorded in `.ai/GOTCHAS.md`; once enough accumulate, `/distill` turns them into rules. Anything a hook can block is not written as a prompt.

## Repository contents

| Directory / file | What it is | Where it goes |
|---|---|---|
| `templates/global/AGENTS.md` | Personal preferences shared across tools | `~/.ai/AGENTS.md` |
| `templates/global/claude-CLAUDE.md` | Claude Code global entry file | `~/.claude/CLAUDE.md` |
| `templates/global/codex-AGENTS.md` | Codex global entry file | `~/.codex/AGENTS.md` |
| `templates/project/` | Templates for the project `AGENTS.md` and the three `.ai/` memory files | The three `.ai/` files are copied to `~/.ai/templates/`; inside a project they are generated by `initai` |
| `skills/wrap`, `skills/distill` | Session wrap-up; distilling experience into rules | `~/.agents/skills/<name>` is a symlink to the repo; `~/.claude/skills/<name>` and `~/.codex/skills/<name>` are symlinks to `~/.agents/skills/<name>` |
| `claude/agents/` | Four tiers of implementer agents plus `verifier` | Copied to `~/.claude/agents/` |
| `claude/hooks/` | `guard.sh` (dangerous-command guardrail), `session-start.sh` (injects progress); `guard_test.sh` is its test | Everything except `*_test.sh` is copied to `~/.claude/hooks/` and made executable |
| `claude/settings-snippet.json` | Snippet that registers the hooks above | Not installed automatically; merge it into `~/.claude/settings.json` by hand |
| `mods/` | Claude Code plugins `token-weather` and `turn-signals` | Not installed; load with `--plugin-dir` |
| `zh-CN/` | Chinese mirror: templates, skill bodies (`SKILL.md` and references; `scripts` is a symlink to the default scripts), agent bodies | Used instead of the defaults with `install.sh --lang zh-CN` |
| `docs/` | Write-ups: English in `docs/`, Chinese in `docs/zh-CN/` | Not installed |
| `scripts/`, `shell/` | `scripts/init-ai.sh`, `scripts/newproj.sh`; `shell/ai-kit.sh` provides `initai` / `newproj` / `checkgit` | Append one line to your shell rc that sources `shell/ai-kit.sh` |
| `tests/` | `tests/install_test.sh`, which tests installation under a throwaway HOME | Not installed |

## Install

```bash
git clone https://github.com/theosong-dev/ai-kit.git ~/Projects/ai-kit
cd ~/Projects/ai-kit
bash install.sh --dry-run   # only prints what would be done
bash install.sh
```

| Option | Effect |
|---|---|
| `--dry-run` | Print only; write nothing |
| `--lang <en\|zh-CN>` | Language of the installed templates, skill bodies, and agent bodies; default `en` |
| `--no-skill` | Don't install `wrap` / `distill` |
| `--no-claude` | Don't copy `claude/agents` or `claude/hooks` |
| `--no-codex` | Don't write `~/.codex/AGENTS.md`; don't create the `~/.codex/skills/` symlinks |

By default the English version is installed; `--lang zh-CN` installs the Chinese version, taking templates, skill bodies, and agent bodies from `zh-CN/`. Both languages share the same scripts (their output is English, and `/wrap` and `/distill` recognize both English and Chinese section names in the memory files) and the same hooks. With `--lang zh-CN`, the first run that sets up your shell rc also writes `export AI_KIT_LANG=zh-CN` above the source line; `initai` and `newproj` read `AI_KIT_LANG` to pick the project templates (`zh-CN/templates/project/` for `zh-CN`, otherwise `templates/project/`). If your rc was already set up, the line is not added and the install prints it for you to add by hand.

Switching languages after one has been installed does not replace anything: existing files that differ are reported as `skip`, and skill symlinks that point to the other language are left unchanged. To switch, move the old files and symlinks (`~/.ai/templates/`, `~/.agents/skills/wrap`, `~/.agents/skills/distill`, the agents in `~/.claude/agents/`, and the entry files if you want them regenerated) out of the way first, then re-run `install.sh` with the other `--lang`.

**It never overwrites any existing file** (including real directories and dangling symlinks). When a target already exists, it prints a single line:

- `ok`: the content is identical, or the symlink already points to the same place (relative-path symlinks count too).
- `skip ... Compare: diff ...`: the content differs or the link points elsewhere, and nothing was changed; compare with the `diff` command shown and merge by hand.
- `create` / `link` / `write`: this run created a file or symlink, or appended lines to your shell rc.
- `warn` / `note` / `error`: a missing source, an old-layout symlink or a fallback, or an invalid option.

It can be re-run safely; the second run no longer prints `create` / `link` / `write`. It does no git operations and does not touch `~/.claude/settings.json`.

Manual steps after installing:

1. Open a new terminal, or `source` your shell rc.
2. Edit `~/.ai/AGENTS.md` and fill in your own preferences.
3. Merge the `hooks` from `claude/settings-snippet.json` into `~/.claude/settings.json`.
4. Mods: `claude --plugin-dir <ai-kit>/mods`; see `mods/README.md` for details.

## Upgrading from an older ai-kit

The old version symlinked `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` to `~/.ai/AGENTS.md`. The new version is "shared preferences plus one entry file per host": `~/.ai/AGENTS.md` holds only the shared preferences, and the two entry files are independent, each referencing the shared file first and then adding that tool's own configuration.

`install.sh` leaves old symlinks alone and only prints a `note`. To migrate:

```bash
rm ~/.claude/CLAUDE.md ~/.codex/AGENTS.md   # removes the symlinks only
bash install.sh                             # generates the entry files from the templates
```

Then move anything in `~/.ai/AGENTS.md` that belongs to a single tool into the corresponding entry file. The old problem where reinstalling overwrote the wrap skill is fixed: an existing skill directory is never touched.

## Enabling it in a project

- `initai`: in the current project, generates `AGENTS.md`, a `CLAUDE.md -> AGENTS.md` symlink, and `.ai/PROGRESS.md`, `.ai/DECISIONS.md`, `.ai/GOTCHAS.md`; anything that already exists is skipped. With `AI_KIT_LANG=zh-CN` it uses the Chinese templates.
- `newproj <project-name> [parent-dir]`: creates the directory, runs `git init`, writes `.gitignore` and the files above, and leaves you in the new directory. The parent directory defaults to `$AI_KIT_PROJECTS_DIR`, or `~/Projects` if unset.
- `checkgit [dir]`: lists the subprojects under that directory that have not been `git init`ed.

## Daily use

- Read `.ai/PROGRESS.md` at the start of a session; if the SessionStart hook is registered, it is injected automatically.
- Before ending, run `/wrap`: it updates progress and next steps, and syncs `.ai/DECISIONS.md` / `.ai/GOTCHAS.md` when there are decisions or gotchas.
- Once enough has accumulated, run `/distill`: it distills repeated or costly gotchas into rules, puts each in exactly one of shared rules, a skill, or a hook, and deletes outdated rules.

The main session only plans, writes briefs, and verifies; implementation goes to one tier of implementer agent by difficulty, and when it finishes a `verifier` is dispatched, given only the task requirements, the diff, and the acceptance criteria. The reasoning is in `docs/02-main-session-and-implementers.md`.

## Platform support and known limitations

- Tested: macOS. `bash tests/install_test.sh` passes under macOS bash 3.2 and bash 5.x (it only uses a throwaway HOME).
- Not tested: Linux, Windows, WSL, Git Bash.
- When symlinks are unavailable it falls back to copying (which does not follow repo updates); that branch has never actually been triggered.
- The English skills, agents, and templates were translated from the Chinese versions. They have been checked at the format and script level (install tests, script fixtures, verdict parsing), but the behavior of the two language versions has not been compared on real long-running tasks.
- On the Codex side there are only the entry template and the shared skills; `claude/agents`, `claude/hooks`, and `mods/` are Claude Code only.
