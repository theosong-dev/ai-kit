# 会话收尾协议

本 skill 是 AGENTS.md「项目记忆协议」在 Claude Code 与 Codex 上的共享触发器。
事实源是 AGENTS.md;本文件只负责把那段协议变成一个 wrap 动作。

## 执行步骤

1. 回顾本次会话,区分四类信息:
   - **进度**:完成了什么、当前状态、下一步、新增的遗留事项。
   - **决策**:做了哪些会影响后续工作的技术 / 产品选择。
   - **踩坑**:哪些方案试过但失败了。
   - **纠正**:本次对话里用户明确指出 agent 做错 / 做多 / 做少 / 方向不对的地方。没有就不写。

2. 更新 `.ai/PROGRESS.md`:
   - 刷新「当前状态」「下一步」「遗留 / 待澄清」。
   - 「进度日志」最上方加一行(日期 + 一句话)。
   - 把本次的「纠正」追加到「用户纠正(待蒸馏)」段(每条一行:日期 —— 用户纠正了什么 → 应该怎么做)。没有就不动这段。
   - 勾选「任务清单」中**已端到端验证**的项;未验证的不勾。
   - 更新顶部「最后更新」日期。

3. **体积 / 结构检查(确定性命令,不靠目测)**。写完后以本次读取的 `SKILL.md` 所在目录为 skill 根目录,用脚本绝对路径执行并显式传目标项目根(两条路径分别加引号):

   `bash "<SKILL_ROOT>/scripts/check_size.sh" "<PROJECT_ROOT>"`

   将占位符替换为实际绝对路径;不依赖当前工作目录或宿主注入的环境变量。脚本支持项目路径含空格。

   按它的输出处理(上限值、段名规则、各项 OK / OVER 判据都在脚本里,这里不复述):
   - 任一项 **OVER**:超出的「进度日志」条目**追加**到 `.ai/archive/PROGRESS-YYYY-MM.md`(按归档时年月命名,目录不存在就 `mkdir -p`),archive 留原文全文,本文件只留压缩后的一行;「当前状态」超行则压缩,保留正在进行的事项与警示状态(未 push / 未验证 / 严禁发版),去掉实现细节。
   - 结构 **DRIFT**(缺段 / 重复段 / 多余顶层小节):先归位——多余小节信息压成进度日志一行、原文整段移入 archive,缺的段补回模板。
   - 归位 / 归档后**再跑一次脚本确认 exit 0**,然后写本次更新。
   - 理由:PROGRESS 是每次会话开头都读的 handoff 文件,体积直接吃 context;历史细节 git log 和 archive 里都有。

4. 仅当本次确有决策时,追加到 `.ai/DECISIONS.md`(只增不改),按其模板:背景、选了什么、放弃的备选、风险。

5. 仅当本次确有失败方案时,追加到 `.ai/GOTCHAS.md`(只增不改),按其模板:试过什么、结果、原因、现在的做法。

6. **蒸馏提醒**:以本次读取的 skill 根目录定位相邻共享 skill 的收集器,执行 `bash "<SKILL_ROOT>/../distill/scripts/pending.sh" "<PROJECT_ROOT>"`(占位符替换为实际绝对路径)。只运行确定性收集脚本,不触发 distill 流程。取输出 [1] GOTCHAS 的 `count` 与 [3] 用户纠正的 `lines`,用算术命令相加,不要把模板标题或已 distilled 条目计入。
   合计 ≥ 8 条时,在收尾汇报末尾提示一句「未蒸馏经验已积累 N 条,建议跑 /distill」。**只提示,不自动跑。**

## 注意

- 没有决策就不硬写 DECISIONS;没踩坑就不硬写 GOTCHAS;没纠正就不硬写「用户纠正」。宁缺毋滥。
- 提炼要具体可执行,不写「继续推进」这类空话。
- 更新完简短汇报改了哪几个文件,不复述全文。

## 附带脚本

- `scripts/check_size.sh [PROJECT_ROOT]` —— 步骤 3 的体积 / 结构检查,bash + awk,显式传目标项目根;超限或漂移 exit 1。
