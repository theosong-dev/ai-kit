# 让模型的输出更好读：速查

来源：Karpathy 2026-10-02 的推文(https://x.com/karpathy/status/2105819303471976479)，正文、配图和 50 条回复已读。ASD-STE100 的规则细节来自模型已有知识和推文配图，未核对规范原文。

用途：要读懂一份长输出(调研报告、方案、陌生系统的解释)时，从这里复制一句话加到请求里。

## 核心想法

模型干的活越多，人的工作越集中在监督和理解，瓶颈变成「读懂输出的速度」。代码和智能变便宜了，可以让模型为「帮我看懂」专门做一次性的产物。

## 四档输出形式(越往下越好读，也越贵)

| 档 | 怎么要 | 适合 |
| --- | --- | --- |
| 1. 受限写作 | 见下方提示词 | 一段解释看不懂、报告太绕 |
| 2. 图 | 「画一张图说明 X」 | 结构、流程、层级、对比 |
| 3. 网页 | 「结论用一页 HTML，带对比表和结构图」 | 要读懂后做决策的调研报告 |
| 4. 讲解视频 | 「做一个 3b1b 风格的视频讲 X」(配音需 ElevenLabs key 或本地替代) | 学一个陌生概念；目前对日常工作用处不明确 |

## 可直接复制的提示词

读英文材料：

```
Explain this in about 80% ASD-STE100.
```

要中文输出(规范只管英语，所以把规则写出来)：

```
按受控技术写作的规则写：同一个东西始终用同一个词；一句只说一件事；
一段只讲一个主题，不超过 6 句；步骤用主动句，一步一条；先给结论再给依据。
```

对已有的一段输出：

```
用上面的规则把这段重写一遍。
```

调研类派单末尾：

```
最终结论用一页 HTML 交付：顶部三句话结论，然后对比表，再配一张结构图；
没查到或没法确认的内容单独列出，并写明查过哪里。
```

## ASD-STE100 是什么

欧洲航空航天工业协会维护的受控英语规范，起源于 1980 年代的飞机维修手册，为母语非英语的维修人员设计。

- 写作规则：步骤句最多 20 词，描述句最多 25 词，每段最多 6 句；一句一个指令；步骤用主动语态和祈使句；不用进行时和完成时；名词堆叠不超过 3 个。
- 词典：约 900 个批准词，每个词只有一个词性和一个意思(`close` 只当动词；`commence` 写成 `start`；`prior to` 写成 `before`)。
- 安全说明：`WARNING` 表示人身伤害风险，`CAUTION` 表示设备损坏风险；先写指令，再写原因。

为什么对提示词有用：模型见过这份规范，一个名字等于同时下了几十条写作指令。它治的正是模型写作的毛病：长句、同义词来回换、一句塞几件事、抽象名词堆叠。

## 注意

- 只在要读懂一份长输出时临时加，**不写进全局规则**。有人反馈全程约束后思考质量下降(单条个人经验)；约束只该作用在最后给人读的那一版。
- 用「80%」而不是 100%：原规范为操作步骤设计，方案比较、决策建议这类需要权衡的内容全套上会生硬。
- 模型只是风格接近，不会真的逐词查词典。
- 好看不等于对。漂亮的讲解如果传达了错误理解反而更危险，HTML 和视频不能替代独立验收。
- HTML 和视频的输出 token 多，输出是最贵的一类，只用在值得读懂的内容上。

## 可能的额外用途(未确认)

规范的本行是设备操作与安全说明。如果你在写设备的英文说明书或屏幕上的英文操作提示，可以单独评估是否按它写。
